UX case study: railway e-ticketing redesign

An independent redesign concept exploring how a national railway booking service can stay information-dense while feeling simple.

1. The existing problem

  • Information overload: dozens of services compete with the one task most people came for — booking a ticket.
  • Flat navigation: PNR, refunds, tourism, food and hotels all sit at the same level as booking.
  • Hard-to-scan results: train name, number, timings, classes, fare and availability are visually similar, so comparison is slow.
  • Colour-only status: availability communicated mainly through colour is a barrier for low-vision and colour-blind passengers.
  • Weak mobile reflow: desktop tables shrink instead of restructuring, forcing horizontal scrolling.
  • Late error feedback: invalid passenger data is often caught only after submission.

2. UX improvements in this redesign

  • Booking-first homepage: the search card is the visual centre; Search Trains is the single dominant call to action.
  • Task-oriented navigation: Book, My Trips, Services, Help — with everything secondary grouped under Services (progressive disclosure).
  • Scannable train cards: a fixed hierarchy of name and number, a departure–arrival timeline, duration, then class chips with fare and availability.
  • Comparison tools: sorting by departure, arrival, duration and price, plus filters for time bands, train type, class, availability and duration.
  • Date discovery: a nearby-date strip shows the cheapest fare and availability for surrounding days.
  • Text-first status: "Available — 42 seats", "RAC 12", "Waitlist — WL 18" — colour reinforces, never carries meaning alone.
  • Error prevention: station selection is constrained to the real station list; passenger fields validate inline with focus moved to the first problem.
  • Trust and honesty: demo data is labelled on every surface that shows a fare, availability, PNR or running status.

3. Implementation

Plain HTML, CSS and JavaScript. No frameworks, no build step, no external data calls — only a web font. State moves through the flow in browser storage.

Homepage → Search → Results → Train selection → Passenger details → Summary → Confirmation
                        ↘ PNR status   ↘ Live train status   ↘ My trips / cancellation / refund
